# Phase 0 research: A-07 enrich and reconcile

No `NEEDS CLARIFICATION` markers remain in the plan's Technical Context — every open question was resolved either in Stage 2's `/speckit-clarify` or in Stage 3's round R2 (D-6 to D-11), drawing on the `oracle` and `mew` design consults in `agent-design.md`. This file records each decision and its rationale rather than re-deriving them.

| Decision | Rationale | Alternatives considered |
| --- | --- | --- |
| No official contractor-identity crosswalk exists between Austin permits and the TX Comptroller (D-10) | `oracle` checked the full column list of Austin's Issued Construction Permits dataset (`3syk-w9eu`) — only name/trade/phone/address fields, no license/tax/registry ID — and the only other candidate source is a city ROW Contractor Registry published as a PDF with its own city license number, not a Comptroller taxpayer number | Checking Austin's broader open-data catalog for an undiscovered dataset — done, found none; treating the PDF registry as a crosswalk — rejected, it's a different identifier namespace entirely |
| AC-2 is proven by a labelled unit fixture, not a live match | Follows directly from the crosswalk finding above; `resolved` is expected at 0 for this run | Waiting for a future Austin API field — out of scope, would block the story indefinitely |
| Travis-only Comptroller lookup scope (342,334 rows), kept as decided at D-1 | Matches the story's stated scope; the statewide set (3,487,662 rows) buys only better `candidate` recall for out-of-county roofers, at ~10x import cost, with zero change to `resolved` (which needs a crosswalk, not a wider name-match pool) | Statewide lookup — rejected per D-6, recorded instead as a manifest limitation (out-of-Travis `candidate` undercount) |
| SOS file number carries via the same fallback as the taxpayer number (`request_identifier` + `source_http_request`) | `mew` found no dedicated lexicon carrier for either field; ADR-0002's nine-field verdict table already established this fallback for the taxpayer number, and the SOS file number is the same class of "sourced but uncarried" field | A new lexicon field just for SOS file number — rejected as unnecessary; the existing fallback already preserves provenance |
| Business record carrier = `company` class under the County data group (no separate corporate-registry class) | `mew` confirmed against the live schema tools and the cached schema set; ADR-0000's proposed `corporate_registry` group was aspirational naming, never a confirmed lexicon group | Filing a new lexicon class for business records — rejected; `company`/County already fits without extension |
| Places carrier: no classed lexicon entity, but `elephant-cli` export of a places table as a side group is proven (Hillsborough, Polk) | `mew` confirmed this via `listPublishedCounties`; Travis's own blocker is its licence-and-release gate (AC-12/13), not a missing carrier | Treating the missing classed carrier as a hard blocker — rejected; the mechanism exists, only Travis's own gate (D-15) decides whether it runs |
| Overture release pinned at `2026-09-23.0` (D-8) | The latest release Stage 0 confirmed reachable in the STAC catalog | Pinning an older, "known-stable" release — not chosen; no instability was found in the latest one |
| Roof-age as-of date = the run's own finish date, 2026-10-22 (D-9) | Matches the estimator's own dry-run default behavior; avoids inventing a separate fixed historical date that the estimator wasn't designed around | A fixed historical date — rejected; would require extra plumbing the estimator doesn't expose cleanly |
| robots.txt fetch does not count toward the BBB 7-request cap | `oracle`: a robots.txt fetch is a precondition check, not a profile/page fetch; AC-6 is silent on this, so the distinction is made explicit in code and tested against the stub (which serves robots.txt too, so the wrapper's own counter logic is still exercised) | Counting robots.txt toward the 7 — rejected as overly conservative without a textual basis in AC-6 |
| Lexicon extension requests (taxpayer number field; `business_rating` class) stay drafted-only (D-11) | Filing is a PO action (D-3/D-4 standing policy: nothing is filed or uploaded outside the repo in A-07) | Filing them now — rejected; out of scope for this story and this agent |

No new technology choices were needed: every dependency (Restate, Postgres, DuckDB, the vendored kit CLIs, `elephant-cli`) already exists in the repo from A-01–A-04.
