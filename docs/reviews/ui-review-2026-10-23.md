## What was checked

- **Design reference**: `design/prototype/Runs390/768/1440.dc.html` and the
  Coverage/Explore screens. These prototype screens implement the full
  A-13/A-14 feature set (search box, "Ask AI", admin sign-in, location chip,
  pipeline-flow visualisation, timeline Gantt, run-diff charts) — all out of
  scope for A-03. The built Runs/Permits pages are the deliberately reduced
  "walking skeleton" scoped by their own code comments to plan §"Atlas
  element map" and specific FR/TC IDs, so a literal 1:1 match to the rich
  prototype screens is not the correct target; the prototype's _token usage
  and component vocabulary_ (cards, pills, provenance line, list items) is
  the right level of comparison, and the build matches it.
- **Atlas tokens**: diffed `apps/web/src/styles/tokens.css` against
  `../assessment-guide/design-system/tokens.css` — `--space-*` and
  `--status-*` values are identical; no drift.
- **Components**: `AppShell`, `Provenance`, `MissingReason`, `StatusPill`,
  `CidDisplay`, `FallbackChip`, `EmptyState`, `ErrorBanner`,
  `LinearProgress`, `Skeleton`, `EngineLine`, `Icon` — all use only
  `tokens.css` custom properties, every data display carries a provenance
  line (source URL/CID/run ID or index+manifest), and every absent value
  renders a `MissingReason` pill with a real reason label (never blank,
  "—", or "N/A").
- **Responsive behaviour**: `AppShell.module.css` (bottom nav < 600px →
  rail ≥ 600px), `Permits.module.css` (cards < 600px → table ≥ 600px, 48px
  tap targets via `--space-9`), `Runs.module.css` coverage-row breakpoint —
  all consistent with the Atlas 600px compact bound and mobile-first order.
- **Commit history** on these files (`git log` on the touched paths): three
  A-03 commits, the most recent (`660f73c`) already a defect-fix commit
  (ERR-10…13: Arrow rows, fixed error text, button font, landmark order).
  No revert/override pattern found.
- **Existing test coverage**: `apps/web/test/*` (166 tests) plus a dedicated
  real-device responsive spec, `tests/e2e/responsive.spec.ts`
  (`A-03-TC-NF-03`), which already runs Permits/Runs at 390/768/1440 against
  the hosted URL and asserts no horizontal overflow, 48px tap targets at
