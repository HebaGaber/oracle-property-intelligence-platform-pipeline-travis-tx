# ERR-63: open_days counts an interval for permits whose work was finished

## Brief description

In published Run 2, `v_roofing_permit.open_days` equals `as_of - issue_date` on all 1,754 open and stalled rows. But 952 of the 1,674 stalled permits (source status Expired) and 7 of the 80 open ones carry a `final_date`: the work was completed and Expired is an administrative lapse. Example: permit 1984-025453 BP was issued 1984-09-12, completed 1985-03-11, expired 2007-08-29; Run 2 shows `open_days` 15,382. So 959 permits looked long-open when they were not (65% of the 1,503 permits "older than 5 years"). Four open or stalled rows also have a `final_date` before the `issue_date`.

## Related requirement

- **Story:** A-11 and A-02 (FR-002, clarification on `open_days`) · **Consumer:** Task B (roofing CRM) long-open filter

## Impact and severity

- **Severity:** High. A sales lead list built on `open_days` would include 959 false "long-open" leads. Run 2 data itself is correct (it carries `final_date` and `issue_date`); only the derived column misleads.

## Resolution

| Field | Value |
| --- | --- |
| Rule | `open_days = as_of - issue_date` only for `status_class` open or stalled, with an `issue_date`, and **no** `final_date`. A plausible `final_date` (not before `issue_date`, not after `as_of`, the same test the roof-age terminal date uses) gives `open_days` NULL with reason `not_open` (existing vocabulary, label "Permit is not open"). A `final_date` before `issue_date` or after `as_of` is a data-quality gap: `open_days` NULL with reason `needs_review`. `status_class` is unchanged (it stays the class of the source status, so Expired stays stalled) and `is_open` still mirrors `status_class = 'open'`; the long-open signal is `open_days IS NOT NULL` and above the threshold. |
| Why this rule | Smallest change: no new column, no new reason, no change to `status_class` (which also drives the roof-age terminal anchor, so roof ages cannot move), and Task B's vendored `MISSING_REASONS` already accepts `not_open` and `needs_review`. |
| Where | `packages/query-core/src/derive.ts` (`openDays`, `openDaysReason`, macros `open_days` and `open_days_reason` now take `as_of` and `final_date`), `packages/query-core/views.sql` (v_roofing_permit passes `final_date`), `packages/contract/src/columns.ts` (open_days meaning and source text), contract/v1 `columns.json` and `README.md` (regenerated by `cut-sample`, plus an "Open duration" paragraph from `scripts/contract-docs.ts`), specs/002-data-contract/spec.md, testplans/A-02-test-cases.md. |
| Data re-export | Not needed. `open_days` is computed by the views from `final_date`, `issue_date` and the manifest `as_of`; no published table carries it. The permits write path (`pipeline/oracle-runtime/travis/permits/write-group.ts`) is unchanged. The internal Query DB open_days column (A-04 track, `pipeline/oracle-runtime/travis/permits/open-days.ts`) is internal reconciliation and not published; it keeps its A-04 definition. |
| Same change | `v_roofing_permit.request_identifier` added (the permit record's request identifier; equals `permit_number` on all 15,025 Run 2 permits), so Task B can key leads on it. The 20-row sample keeps the property's `request_identifier` and omits the permit's. `property_cid` and `permit_cid` are untouched. |
| Counts on the Run 2 export (read-only, local parts, views bound as the app binds them) | before: open_days set on 1,754 (80 open, 1,674 stalled); older than 5 years 1,503; older than 10 years 1,311. after: set on 795 (73 open, 722 stalled); older than 5 years 548 (all stalled); older than 10 years 356. NULL: 955 finished (reason not_open), 4 final_date before issue_date (reason needs_review). |
| How it escaped | The A-02 rule was written as "as_of minus issue_date for open and stalled", and the pilot Expired permits had no completion date, so no test or fixture combined an Expired status with a `final_date`. |
| Tests that pin it | query-core `test/open-days-finished.test.ts` (views over a fixture: Expired with final_date, Permitted with final_date, no final_date, final before issue, final after as_of, closed; request_identifier); `test/derive.test.ts` (TS and DuckDB macro agree, including the new cases). |
