## Action

1. Open the preview in a private window and go to Explore, **AI** tab. The counter reads "0 of 10" questions.
2. Ask the G1 prompt: "Which properties in Travis County within five miles of Pflugerville have roofs older than 15 years?" Then, in the same session, the G2 follow-up "Which properties near that area have open roofing permits that have been open for many years, and who is the listed contractor?"
3. Ask G6 (ZIP 99999), G4 (Lakeway) and G5 (a permit number). The page cannot pin a manifest, so these run on the **latest** run (the full county).
4. Open Help, **MCP**, pick `search_properties`, press "Try a tool". The result comes through the server-side proxy; no token is in the browser.
5. In a terminal, call `https://s7h96zfam0.execute-api.eu-north-1.amazonaws.com/mcp` with and without the bearer token (the Playwright MCP project does this; the PO ran it with the token held in the shell). Open MCP Inspector against the same URL (see `docs/mcp.md`).
6. Run the golden queries at API level, pinned to the small run (`tests/agent`).

## Missing data or limitations seen

- **Full county not served (PO exception).** On Run 1 and Run 2 any call that reads property data ends in the Lambda timeout; the agent and the MCP data tools answer only on the small run. The AI tab on the latest run shows an error state.
- **Answers on the small run are mostly "no match".** The AC-8 three-way agreement (agent, MCP, Explore) is true only vacuously (both sets empty). The `truncated: true` row cap case and the stalled-permit cases (TC-017) need the full county.
- **The published export has no contractor name, no BBB status and no owner mailing location.** The agent and MCP say so, with the reason, instead of returning a guess; this is correct.
- **MCP burst answers 503, not 429, for most excess calls.** Accepted deviation (ERR-64).
- **Not measured:** an `AI_PROVIDER=gateway` run (TC-011), the SSM fail-fast ops check on a staging stack (TC-028), full-county latency, CI, the token-leak counts.

## Defects found by the hosted runs

Six deploy-time fixes, each found by the first hosted call and invisible to the unit, contract and CDK tests (`docs/decisions/DEC-A-14-agent-mcp-full-county.md`):

1. The route throttle settings named routes that CloudFormation had not created yet (the first deploy rolled back cleanly); the stages now depend on their routes.
2. The Amplify `/api/<*>` rewrite pointed at the query API, which has no `/agent` route; a more specific `/api/agent/<*>` rewrite now points at the agent API.
3. The agent, MCP server and "Try a tool" proxy read the run list from an S3 key that is never published; they now fetch the site's own `/runs/index.json` (`RUNS_INDEX_URL`).
4. The agent role had no Bedrock permission; it may now invoke only the `eu.anthropic.claude-sonnet-4-6` profile and the base model only through it (commits `532521c`, `1bea648`).
5. The agent and MCP Lambdas run at 3,008 MB (amendment AM-09; 1,769 MB ran out of memory), commit `16a7eb1`.
6. The agent and MCP engines bind only the views a query reads (the ERR-19 rule), commit `a74fd89`.
