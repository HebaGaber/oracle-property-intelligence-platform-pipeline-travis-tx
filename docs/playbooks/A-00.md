## Design in Claude Design (D1–D9)

Menu names in Claude Design change between releases; the steps say what to do, use the control your version shows.

### D1 Prepare the design pack

Collect these files in one folder (for example `~/Desktop/design-pack-A/`):

- [ ] `assessment-guide/design-system/design-system.md`, `tokens.css`, `tokens.json`, `preview.html`
- [ ] `docs/01-intent.md`, `docs/feature-list.md` from this repo
- [ ] `README.md` of this repo (the demo transcript is the script the screens must perform)

### D2 Set up the design system (once; reuse it for both apps)

In Claude Design, create a design system (organization or project design system) and upload the four design-system files. Then send:

```text
This is the Atlas design system: a Google Material 3 theme for two apps (Oracle Explorer and a
Roofing CRM). Read design-system.md fully. Treat tokens.css as the only source of colour, type,
spacing, radius and motion values. Confirm by listing: the colour roles, the type scale, the
window size classes, the components in section 7, the data-honesty elements in section 8, the
required states in section 9, and the eight signature moments in section 14.2. Do not design yet.
```

> **Claude Design's confirmation →** {anything it misread, which you corrected}

### D3 Start the project with the brief

Create a new prototype project, attach the design pack, select the Atlas design system, and paste the **Brief: Task A, Oracle Explorer** from [templates/design-brief.md](../../../assessment-guide/templates/design-brief.md) (both paragraphs, including the opening line).

### D4 Build screen by screen

Send one prompt per screen. Wait for each, review it, then send the next.

```text
Build the {screen name} screen, mobile first at 390 px, then 768 and 1440. Use only Atlas
tokens and components. Show these states as separate frames: loading, empty, error, partial data,
rate-limited (if it fetches from IPFS), populated. Put the provenance line where it is visible
without scrolling. Label the demo transcript line this screen performs: {line}.
```

### D5 Make the signature moments interactive

One prompt per moment listed in the brief:

```text
Make signature moment #{n} ({name}) from design-system § 14.2 a clickable interaction in the
prototype: {how it behaves, copied from the table}. Add the visible button alternative for every
gesture, keyboard behaviour, and the prefers-reduced-motion fallback. Show it on 390 and 1440.
```

### D6 Walk the demo

```text
Walk through README.md's demo transcript line by line in the prototype. For each line, name the
screen and state that performs it and click through it. List every line that has no screen, or
needs a state that does not exist yet, then build the missing pieces.
```

### D7 Self-check before export

```text
Audit every screen: list any colour, font, radius or spacing value that is not an Atlas token;
any missing state from section 9; any data display without provenance or a not-available state;
contrast below 4.5:1; touch targets below 48 dp; gestures without a button. Fix them, and add
every new component to the Extensions log with the reason.
```

### D8 Export and bring it back into the repo

1. **Handoff to Claude Code:** use Claude Design's export or handoff to Claude Code. It gives you a bundle or a command to paste. Paste it into Claude Code in this repo, and tell it: `Save the handoff into design/claude-design/ without changing any app code.`
2. If the handoff fails, **download the project zip**, then:

```bash
mkdir -p design/claude-design && unzip -o ~/Downloads/{your-export}.zip -d design/claude-design
```

3. Also export **standalone HTML** and a **PDF** into `design/claude-design/`.
4. Turn the export into the files the stories use:

```text
Read design/claude-design/ (the Claude Design export). Without writing app code, create:
- design/flows.md: each user flow as numbered steps with a Mermaid flowchart
- design/screens.md: one row per screen with its states, components used, signature moments,
  breakpoints and the demo line it performs
- design/tokens.json: copied from ../assessment-guide/design-system/tokens.json, plus any token the
  export added (flag those)
- design/screens/: one PNG per screen and state if the export has them
- docs/02-design.md: a table of demo line → screen → state
List anything in the export that uses a non-Atlas value.
```

```bash
git add design docs/02-design.md && git commit -m "design: Claude Design export and screen inventory"
```
