## Draft acceptance criteria (put these in the story file, then edit)

As a **CRM developer**, I want **a frozen, documented set of query views with real sample rows**, so that **the Explorer, the agent, MCP and the Roofing CRM all query the same columns**.

1. Given the lexicon tables export-tables produces, when views.sql is applied in DuckDB, then v_property, v_roofing_permit, v_contractor and v_run exist with the documented columns.
2. Given contract/v1/README.md, when a developer reads it, then every column has a meaning, a source and a null policy.
3. Given contract/v1/sample.parquet, when it is opened with DuckDB, then it has 20 real Travis County rows.
4. Given a solar or Auxiliary Power permit, when the roofing classifier runs, then it is not classified as roofing.
5. Given a permit whose contractor has no BBB profile, when it is read from v_roofing_permit, then bbb_rating is null and the reason column says why.
