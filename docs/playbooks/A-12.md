## Draft acceptance criteria (put these in the story file, then edit)

As a **data operator**, I want **windowed refreshes that publish new CIDs and keep history**, so that **the data is shown being ingested over time**.

1. Given at least 3 runs on different days, when Runs opens, then each run shows timestamps, sources, deltas and limitations.
2. Given run N+1, when it publishes, then changed groups get new CIDs and its manifest records previousManifestCid.
3. Given run N's CIDs, when fetched after run N+1, then they still resolve.
4. Given IPNS, when run N+1 finishes, then it resolves to the new manifest.
5. Given the scheduler, when deployed, then it is disabled by default and documented as opt-in.
6. Given a refresh with no source changes, when it runs, then no new data CIDs are produced and the run says no changes.
